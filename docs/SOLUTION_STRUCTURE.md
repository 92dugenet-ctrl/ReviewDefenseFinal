# ReviewDefense — Solution page

This version is a **functional structural prototype**, not final copy.

The purpose is to understand quickly what every section does, what content belongs there,
and how the visitor interacts with it. Text is intentionally indicative and can be rewritten later.

## 01 — Introduction
Purpose: introduce the complete solution without listing features.
Structure: short positioning + one main visual/product area.
Behavior: calm entry; visual is progressively revealed.

## 02 — Questions
Purpose: start from concrete user problems.
Structure: question list on the left + one vertical dynamic result on the right.
Behavior: selecting a question changes the right panel without leaving the page.

## 03 — Comprendre
Purpose: demonstrate that an avis is analyzed beyond its wording.
Structure: one review + three analysis layers.
Behavior: scroll progressively reveals content, context and signals.

## 04 — Décider
Purpose: explain the suspicion score.
Structure: score + contributing signals + explanation.
Behavior: score appears first; signals and rationale are revealed progressively.

## 05 — Agir
Purpose: connect analysis to an appropriate action.
Structure: analysis → recommendation → human choice.
Behavior: user can validate, modify or refuse the recommendation.

## 06 — Interface
Purpose: consolidate the whole product journey.
Structure: one product frame containing review, analysis, recommendation and validation.
Behavior: interface can be assembled progressively during scroll.

## 07 — Conclusion
Purpose: close the story and lead naturally to the first action.
Structure: one message + one CTA.
Behavior: intentionally minimal.

## Design rule
Do not optimize final wording yet. The important thing at this stage is:
- what the section communicates;
- what elements it contains;
- how the elements relate;
- what changes on scroll/click;
- where future media and final copy will be inserted.
